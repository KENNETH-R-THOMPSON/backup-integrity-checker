# MacBook demonstration, November 3, 2026

This is a reproducible test of the public Python backup checker using invented files. It was run on the target Apple Silicon MacBook, rather than inferred from hosted CI.

## Environment

- macOS on Apple Silicon
- Apple system Python 3.9.6
- Repository commit: `554bbfa` on `main`
- All commands were run from the repository root.

## Run it

```sh
python3 -m unittest discover -s tests -v
python3 examples/demo.py
```

The unit test command reported:

```text
Ran 35 tests in 0.489s

OK (skipped=1)
```

One test specifically requires a Windows directory junction, so it was skipped on macOS. There were no test failures.

The example printed:

```text
Snapshot: recorded 3 synthetic files
Copied backup: 3 unchanged (exit 0)
Clean verification: 3 unchanged (exit 0)
Changed verification: 1 unchanged, 1 changed, 1 missing, 1 unexpected (exit 1)
CSV verification: 4 file statuses checked (exit 1)
status,path
changed,inventory.csv
missing,note.txt
unexpected,extra.txt
unchanged,nested/guide.txt
Changed: inventory.csv
Missing: note.txt
Unexpected: extra.txt
Synthetic restore: 3 files verified in a separate folder (exit 0)
Demo complete. Temporary files were cleaned up.
```

Exit code 1 for the changed verification is intentional: the synthetic folder no longer matches its baseline. The demo itself exited successfully.

## What this demonstrates

The tool records per-file SHA-256 baselines, verifies a copied folder, and classifies files as changed, missing, unexpected, or unchanged. The demonstration also copies a fictional backup to a separate temporary restore directory and checks it against the original baseline.

A passing example doesn't prove that a real NAS backup is recoverable. It doesn't preserve application databases, permissions, metadata, or empty directories, and it doesn't authenticate the baseline. A real recovery test still requires an independently trusted baseline and an actual backup restore under authorized conditions.
